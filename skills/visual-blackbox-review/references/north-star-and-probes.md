# 唯一结果交付北极星与零干扰异常探针备忘总表

> **第一层的终极目标**：不要等用户骂上门或创始人亲眼踩坑才被动救火，而是让未知问题通过**零干扰程序探针**与**纯视觉黑盒验收**主动浮现到眼前。

---

## 一、最高北极星标准：快模型零干扰结果交付探针

**系统内部的日志和借口有一万个，但对用户而言，一次交互成功与否只有一个金标准**：
> 用户发出指令后，在他最终真正收到的可见消息或界面结果里，有没有拿到真实结果？

- 凡是“收到 / 我去处理 / 好的我看一下 / 已安排给某模块”这类过程客套，**一律不算结果**；
- 失忆、静默超时、踢皮球、半途卡死、假 `0` 占位，**一律算未达成**。

### 推荐落地方式（绝不给每个局部模块堆一堆零碎小探针）
搭建一个**完全旁路、对主任务零干扰的轻量快模型探针**：
- **输入**：只喂两段真实记录——`「用户提了什么要求」` + `「用户最后真正收到了什么可见内容」`；
- **输出**：只判二元结果 **`YES` 或 `NO`**；
- **动作**：一旦判 `NO`，立即拉响告警，再由工程团队倒查内部究竟是存丢了、卡死了、路由歪了还是缺提示词。

## 二、零干扰程序探针异常信号总表（按需分批建设）

> **核心约束**：探针本身必须对主链路执行**零干扰、只读旁路**，只吐客观异常信号，绝不侵入主业务逻辑。

### 1. 五类核心主信号
| 类别 | 监测的客观信号 | 背后通常暴露的深层问题 |
| :--- | :--- | :--- |
| **(a) 服务与资损底盘信号** | 服务宕机/持续 5xx、匿名首屏资源非 200（白屏）、客户端安装包 404、资金/配额冻结漂移、死信/僵尸卡单、单租户存储暴涨 | 基础设施故障、发版漏传、并发记账缺陷或无界写入 |
| **(b) 任务上下文异常膨胀** | 单次请求 Prompt Token 或工具说明书体积持续慢毒膨胀、触发高水位告警 | 无关厚手册每轮硬塞、未切片大文件直灌、工具桌无节制堆积 |
| **(c) 推理/完成耗时异常拉长** | 同类常规任务步数或总耗时显著高于基线 | 系统提示词误导模型来回兜圈，或关键工具缺失/返回值噪声太大 |
| **(d) 用户显式埋怨与返工** | 同一诉求反复重发、连续追问否定、跳过系统交互卡片改去外部群截图求助 | 交互断链、前端卡片不好用、或模型屡次答非所问 |
| **(e) 活跃用户突然沉默流失** | 原本高频使用的客户/团队 7 日活跃或消耗断崖骤降、管理者在用但一线断层不用 | 静默体验翻车、信任受损或上手卡点过高 |

### 2. AI/Agent 系统高频隐藏翻车指纹（客观行为探针）
传统监控只看 HTTP 500，对下面这些“全站 HTTP 200 却疯狂烧钱翻车”完全失明，建议逐步接入客观事件台账探针：
- **成本与算力偷跑**：单次巨型上下文炸弹、单话均耗异常飙升、新增计费类别漏统计；
- **循环与重复浪费**：后台闲时任务死循环、同一份文件（同 `sha256`）重复做昂贵解析/OCR、单会话短时间审批/求助卡风暴；
- **Agent 行为翻车指纹**：短时间用完全相同参数重复调同一工具、用户点完确认卡片续跑后几分钟内再次弹出同一张重复卡、工具截断率或报错率飙升、只喊文字预告不调真实工具就结束回合。

## 三、发现层自省两连问（每次由人工/客户先踩出 Bug 时必问）

1. **盲区追问**：为什么这次是人先肉眼踩到，而不是结果交付探针、零干扰监控或纯视觉验收先报出来？是漏了哪类客观信号，还是遥测查询一直盯着旧空表/漏了新字段？
2. **假绿追问**：发布前是不是只信了开发自写的模拟单测，留了“只写后台接口却漏画前端交互”的半截管道，或者重测时忘了清零旧缓存？
