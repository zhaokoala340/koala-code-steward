# 专抓 AI「换皮打补丁惯性」的 5 面硬镜子

> **为什么要留着这 5 面逐轮打回的真实过程镜子？**
> 因为它们照的不是某一个具体业务场景，而是 **AI 写代码时最顽固的本能病**——被抓包一种越权代码后，大脑会立刻换 5 种听起来更“工程化”的马甲，继续往代码里塞业务 `if -> then`、塞黑盒中间关、塞拍脑袋阈值、塞冷却开关和擅自掐流程。
> 无论是设计方案还是独立审码，动刀前拿这 5 面镜子逐一照一遍，绝大多数隐形补丁会当场现形。

---

## 硬镜子 1 · 5 连换皮补丁惯性：业务猜词 → 补词 → 死流程锁 → 特例黑名单 → 特例按钮

- **典型现场**：自动化浏览器任务去电商后台查订单。旁边标签页明明已经登着新版后台，AI 却死磕旧网址，而且每看一眼页面就弹出“请扫码登录”求助卡，用户点继续后它又秒弹一张，陷入无限死循环。
- **连续 5 次换皮错法与逐轮戳穿**：
  1. **错法 1（偷塞业务猜词 + 自动弹卡 + 单页眼罩）**：写浏览器工具时不放心大模型，偷偷在读页面函数里塞了二十几个业务关键词（“扫码登录”“登录超时”……），见字就绕过大脑自动弹求助卡，还把视野锁死在单个标签页。
  2. **错法 2（错上加错往词表补新词 + 加封口令）**：实测遇到新文案没猜中，第一反应不是拆词表，而是继续往词表里加词，再加“强制等待 2 秒 + 立即停止调工具”的封口令，直接酿成死循环。
  3. **错法 3（换皮塞死流程锁）**：拆掉词表后，方案里转头偷加一条“只有当 AI 查完全部标签页后才允许向人发求助卡”——换了个包装，本质依然是用代码替大脑写死业务流程。
  4. **错法 4（用特例黑名单防补丁）**：为了“防止以后再写词表”，提议在检查脚本里加正则专门禁止中文业务词表——明天换英文、换网址照样穿透，拿特例防特例。
  5. **错法 5（造特例遥控器按钮）**：因为今天后台刚好开在旁边标签页，又本能想单造一个“遇到卡顿就切换标签页”的专用按钮——本质依然是针对单次场景的 `if -> then`。
- **一句生活比方**：不肯把真鼠标真键盘交出去，非要自己搓一块越钻越多孔的塑料遥控器，每撞一次墙就多焊一个键。
- **唯一正确落点**：彻底删光基础工具里一切业务/页面状态 `if -> then`、自动弹卡、封口令与特例按钮；收敛为**纯净完整的通用工具 + 物理断线的独立求助工具**，未知现场的推理判断 100% 交还大脑与提示词。

## 硬镜子 2 · 自然语言前置扫词截胡

- **典型现场**：用户在聊天框里提了一个普通写稿需求——“帮我写一篇面向**每天**整理会议纪要的行政同事看的效率文章”。结果大模型压根没收到这句话，系统反手直接建了个莫名其妙的定时提醒。
- **病根**：在用户自然语言送进大模型之前，代码靠正则扫关键字抢话头，一碰见“每天”“每周”就半路截胡代办。
- **一句生活比方**：在老板和聪明助理之间塞了个只认几个关键词的耳背传话员，听见“每天”俩字就在半路把话抢走乱下了单。
- **唯一正确落点**：除用户亲手点击的界面显式按钮或明确斜杠指令外，所有自然语言原封不动直达大模型，代码严禁在进大脑前靠扫词截胡。

## 硬镜子 3 · 4 轮过度设计：从“事后猜假词”到“凡事必经程序中间关”

- **典型现场**：模型跨步调用外部付费接口时，抄错或瞎编了一串 60 位长平台编号，导致白扣费、拉错人。
- **4 轮跑偏药方与层层剥洋葱**：
  1. **错法 1（门口正则事后猜假词）**：在接口前写正则查这串字符像不像“placeholder / xxx”——只要模型编出长得像真的 60 位假号，照样穿透。
  2. **错法 2（拿单个症状当通用规矩）**：只写“长平台编号走短句柄映射”，换个业务对象依然是特例。
  3. **错法 3（只谈抽象原则、只拿表格举例）**：遇上照片（JPG）、演示文稿（PPT）、冷门设计稿（PSD）立刻答不上来。
  4. **错法 4（过度设计“凡事必经程序中间关”）**：试图强行规定不管图片、常规 CSV 还是文档，一律先经过程序黑盒转译成中间对象才能递给模型——反而把原生多模态能力阉割掉了。
- **一句生活比方**：员工能直接肉眼看懂的照片和短单子，没必要非让前台翻译一遍再递给他；这位员工天生不认图就换能看图的员工（换模型），打不开的冷门文件坦诚直说“打不开”，绝不堆黑盒转译中间件和事后猜错补丁。
- **唯一正确落点**：模型能原生直读的内容（图、文、常规文件）直接交有能力的模型读（当前模型读不了就换模型），确实读不了坦诚直说“读不了”；仅对物理绕不开的确定性工作（精确大账、真实二进制生成、敏感凭证或机器长句柄确定性代码注入）使用确定性工具，绝不写事后猜假词正则。

## 硬镜子 4 · 3 轮错法：从暴力硬截断到“隐形程序大小阈值”

- **典型现场**：花钱拉回来的 20 条接口数据被代码从头一刀硬剪得只剩 1 条；知识库短手册每次检索都被截断在第 3 行；全员工具桌越塞越胖，开场几十把工具说明书先吃掉上万字上下文。
- **连续 3 次错法**：
  1. **错法 1（拍脑袋硬截断）**：代码写死 `slice(0, 600)` 静默丢弃后半截。
  2. **错法 2（给单个平台写特制裁剪脚本）**：换个接口或平台照样炸。
  3. **错法 3（换皮再塞隐形程序大小阈值）**：拆了硬剪后，改提议“短内容完整给，大块内容由程序按字数阈值判断并自动改写摘要”——**谁来定多少字算大？靠程序卡死数字再替模型改写，本质仍是换皮 `if -> then`！**
- **一句生活比方**：递给聪明助理一本厚书，不需要前台先拿尺子量厚度、超 10 页就把后半本撕掉或替他重抄；只需交代助理“遇大部头先忠实记目录和结构要点，用到哪章再按需翻阅”。
- **唯一正确落点**：拆光拍脑袋字数阈值的静默截断与程序自动改写，把大内容按需阅读策略交还提示词与分页/目录读取工具；工具桌保持精简克制。

## 硬镜子 5 · 3 轮错法：后台循环暗藏弹窗 → 叠三层冷却 → 遇错擅自掐死循环

- **典型现场**：桌面客户端未获操作系统录屏权限，后台每秒 2 次的截屏定时器不断硬撞接口触发系统授权弹窗，1 分钟在屏幕上叠出 100 个关不掉的弹窗。
- **连续 3 次错法**：
  1. **错法 1（暗藏副作用弹窗）**：把会顺手弹系统授权窗的调用藏在高频后台定时器里。
  2. **错法 2（围着副作用叠三层防抖补丁）**：提议“服务端拦截 + 客户端拦截 + 按钮 5 秒防连点冷却”——典型的拿补丁盖补丁。
  3. **错法 3（顺手改成“定时循环遇报错直接停掉循环”）**：代码擅自替大脑判了整趟任务的死刑，大模型压根不知道发生了什么，也失去了换条路走的机会。
- **一句生活比方**：授权弹窗绝不接在后台闹钟上乱弹；路走不通时，代码既不蒙头撞墙，也不擅自替总经理撤回整笔业务，更不把冰冷红字直接拍给客户——把真实报错原样报回大脑，由大脑定夺下一步或用人话向人交代。
- **唯一正确落点**：“弹权限 / 发起人工打扰”剥离为独立显式工具；任何运行报错既不无脑死撞、也不擅自替大脑终结流程、更不直接甩给用户，一律原样交还大模型判断处理。
