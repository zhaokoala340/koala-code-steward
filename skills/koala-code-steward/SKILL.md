# 考拉代码管家 · 总控导航（Koala Code Steward）

本 Skill 是「考拉代码管家」开源自然语言研发治理体系的**总调度入口**。它负责判断当前任务处在研发闭环的哪一环，自动路由到对应的 **6 个专职子 Skill**，并统一执行**轻/中/重三档流程分量、GitHub 唯一正本、独立制衡与对抗式审查、素描模特原则、绿黄红分级授权、说“好了”必附证据与去代码化统一比喻沟通纪律**。

---

## 零、先定流程分量：轻 / 中 / 重三档（换灯泡不用请监理，动承重墙才走全套）

> 与下文“绿 / 黄 / 红”配套使用：**红黄绿管“能不能直接干”，轻中重管“要走多少道工序”**。拿不准时就高不就低。**“重要代码”即中档、重档的全部改动，上线前一律必须通过对抗式审查**；只有轻档纯展示微调可免。

| 档位 | 典型改动 | 必走工序 | 可省略 |
| :-: | :--- | :--- | :--- |
| **轻** | 改文案、换颜色/图标、调间距、修错别字等纯展示微调，不碰数据、钱、权限与接口 | 快速查一下改动点被哪些地方引用 → 读完相关源码 → 动手 → **在测试环境亲眼看到改后效果并附证据** | 图谱全量排查、独立对抗式审码、多线并发黑盒 |
| **中** | 封闭清单内新增或调整一个功能、修复用户可见 Bug | 查图谱看影响面 + 读真源码 → 先写好「当……时，应该……」验收标准 → 施工 → 在测试环境做纯视觉黑盒验收 → **上线前交独立会话做对抗式审码** → 修 Bug 时简要追原则（必要时沉淀错题本） | 黄灯决策卡（未触黄灯边界时） |
| **重** | 动数据结构/历史数据、钱与计费、登录与权限、跨端接口、引入外部依赖，或任何触及黄灯边界的改动 | **全链路 6 站全走**：先交黄灯决策卡拍板（拿不定主意时推荐红蓝对抗）→ 立/改蓝图与字段表 → 图谱 + 源码 → 施工 → 测试环境纯视觉黑盒 + **独立对抗式审码（建议多个独立审查方从不同角度进攻）** → 追原则沉淀 | 无 |

## 一、全链路 6 站路由表（绝不跳层直接蒙头改代码）

| 当前阶段 / 你的目标 | 立即激活的子 Skill | 核心产出 |
| :--- | :--- | :--- |

| **审出违宪 / 测出 Bug / 线上客户踩坑** | `root-cause-and-best-practices` | 灵魂两连问（追缺失原则 → 借图谱与检索全仓查一再查十）→ 按「素描模特原则」对照可靠开源代码结构降幻觉（未经授权绝不直接搬运）→ 升维整改并同船回写 GitHub 活态错题本 |

## 二、贯穿全流程的 6 条不可妥协铁律

1. **GitHub `main` 是唯一正本，多 Agent 绝不互相改坏断档**
   - 宪法、蓝图、字段表、边界、错题本与重大决策记录全部常驻 GitHub `main`；没合入 `main` 的规矩不算生效。
   - 每个 Agent 开工前必拉最新 `origin/main` 并开独立分支/worktree；改前查图且必读真源码；遇他方 PR 在合先礼让、`rebase` 并重验门禁后再合；PR 必留前因后果、规则文档与代码同船合入。
2. **干活与验收物理分离（`Generator ≠ Evaluator`），重要代码上线前必过对抗式审查**
   - 写代码的对话绝不兼任自己的终审裁判。核心代码合入与高影响交付，必须交给干净独立上下文的审码官或纯视觉测试官验收，并锁死被审精确 `commit SHA`。
   - **重要代码（中、重档）上线前必须先做对抗式审查**：审查方不是“看看合不合规矩”，而是默认这份改动有坑、主动从极端输入、并发重复、越权绕过、中途失败、历史数据、回滚退路、钱与额度对账等角度想办法把它弄坏，并逐条留下“怎么攻、结果如何”的攻击记录；拿不出攻击记录不得放行（详见 `first-principles-code-review` 第三点五节）。
3. **「素描模特原则」防幻觉、守授权边界**
   - 遇到有明确可靠开源代码的领域，允许且鼓励先读对方的真实代码结构并评估适用性——就像画画前摆一位素描模特，防止 AI 凭空脑补；但**原则上未经用户明确授权，绝不直接引用、复制或引入他方开源代码**。
4. **绿 / 黄 / 红三级决策边界**
   - **🟢 绿灯直接闭环**：无架构/产品代价的纯技术修复、防崩溃、去重、补测试，以及线上 P0 紧急止血（止血后补全复盘与独立验证）。
   - **🟡 黄灯坚决停手**：触及新增或大改核心数据结构、跨端协议、长期权限架构、商业计价/产品体验显著取舍，或引入新外部依赖/开源代码时，**严禁先斩后奏**——用生活化比方呈交 **5 行白话决策卡**等决策者 30 秒拍板。
   - **用户拿不定主意时，主动推荐红蓝对抗**：凡黄灯决策、或用户对某个方案分岔明显犹豫不决，主动推荐并询问用户：“要不要开 2–3 个互相独立的子智能体做一次红蓝对抗？”——红方专找这个方案的风险、代价与失败场景，蓝方专论证它的价值与可行性（必要时再加一位中立裁判汇总）；各方独立思考、互不看对方草稿。用户同意才开；辩完把双方最强论据与仍存分歧压缩进 5 行决策卡，**最终仍由用户拍板**。当前工具不支持子智能体时，可用多个独立新对话代替。
   - **🔴 红灯零容忍**：隐私/凭据泄露、生产高危数据破坏、越权绕过隔离或擅自魔改底层框架，第一秒止损脱敏并堵死源头。
   - **数据疑似丢失时绝不下“无法恢复”的结论**：AI 判断出现“数据没了 / 备份没了 / 回滚不了”时，只能如实报告看到的现象，并用大白话告诉用户**去哪个后台、点哪里亲眼核实备份与恢复入口**；同时明确提醒用户：**AI 关于“恢复不了”的判断不可轻信，以后台亲眼所见为准**。在用户核实前，禁止为“补救”再做任何删除、覆盖或重建操作。
5. **默认用户不懂代码：去代码去字段、讲透细节、唯一比喻词典 + 根源外置交接单**
   - **面向用户（聊天汇报、方案对齐、监理单、黄灯决策卡）**：默认用户不懂代码和编程，必须**彻底去代码化、去字段化**（不甩变量名、表名、字段名、英文代码黑话），同时**解释清楚必要的运转细节与取舍利弊**（不拿一句空话敷衍）；
   - **统一项目比喻词典**：打比方必须基于本项目真实的代码逻辑，在 `PRODUCT_BLUEPRINT.md` 中定死**一套贯穿全项目生命周期的唯一比喻**，此后所有对话与不同 Agent 一律沿用同一套比喻，严禁今天换餐馆、明天换火车给用户增加额外认知负担；
   - **问题根源外置成 Markdown 交接单**：遇到重要缺陷或架构根因，必须同步外置为自包含的 Markdown 文件（`docs/handoffs/<日期>-<主题>-root-cause.md`，写齐代码仓路径、分支、精确 `commit SHA`、文件行号、报错与源码摘录、根因与待审问题），方便用户直接拎着这一个文件新开对话或丢给更高智力的 Agent 无缝接手 Review。
6. **说“好了”必须附上刚刚亲手跑出来的证据**
   - 任何一句“已完成 / 已修复 / 测试通过 / 部署成功 / 页面正常”，都必须紧跟**本轮刚刚亲手执行得到的真实结果**：执行了什么检查、实际输出或截图是什么、对应哪个精确 `commit SHA`；
   - 拿不出刚跑出来的证据，就只能如实说“改动已写好，**尚未验证**”，绝不凭“应该没问题”“按理说能过”或上一轮的旧结果宣告完成。

## 三、开箱启动检查清单

如果当前项目尚未搭建这套治理底座，按顺序引导用户完成初始化（用户不懂代码，每一项都由 AI 代为操作并用大白话解释“这是什么、为什么需要”）：
- [ ] **主动询问是否把本套 Skill 的调用约定写进项目 `AGENTS.md`**：向用户说明“写进去之后，以后任何新对话、任何 AI 一进项目都会自动按这套流程干活，不会漏用”；用户同意后，把 [`constitution-blueprint/templates/AGENTS_TEMPLATE.md`](../constitution-blueprint/templates/AGENTS_TEMPLATE.md) §0「本项目研发 Skill 调用约定」写入（或合并进）项目根目录 `AGENTS.md`（使用 Claude Code 时可软链 `CLAUDE.md`）。
- [ ] **已在 GitHub 建仓**并保护 `main` 分支，已配置 `.github/pull_request_template.md` 与 `docs/decisions/`（启用 `github-shared-truth`）。**原则上优先推荐 GitHub**；若用户确实暂时无法使用 GitHub，按 `github-shared-truth` 第三节结合用户实际情况推荐入门模式，并约定条件成熟后升级。
- [ ] **主动建议开辟一套测试环境，与正式环境彻底分开**：不懂代码的用户往往不知道“测试环境”的存在。要用大白话讲清：测试环境就像餐馆正式开门前的试菜厨房——新菜先在这里做、先在这里尝，确认没问题再端给真客人；不分开的话，每次上线都可能把新问题直接甩给真实用户、弄坏真实数据。征得同意后协助搭建，此后中、重档改动**一律先在测试环境验收通过，再用同一个 `commit SHA` 发布到正式环境**；AI 日常开发与调试只碰测试环境，要动正式环境（发布、改数据）前必须征得用户明确同意。**例外**：线上 P0 紧急止血（全站白屏、宕机、资损）经用户同意可直接处理正式环境，止血后须在测试环境补验并补复盘。
- [ ] 已联动 `grill-me` 共建并在 GitHub `main` 落盘五件套：`AGENTS.md`（可软链 `CLAUDE.md`）、`PRODUCT_BLUEPRINT.md`（含「当……时，应该……」验收标准）、`PROTOCOL_FIELDS.md`、`BOUNDARIES.md`、`MISTAKE_BOOK.md`（启用 `constitution-blueprint`）
- [ ] 已为当前仓库建立本地代码知识图谱（`code-review-graph build`），并确认 `.code-review-graph/` 已加入 `.gitignore`（启用 `code-review-graph`）
- [ ] 已有极简机械门禁脚本（如 `scripts/check-gates.mjs`）拦截低级机械违规
