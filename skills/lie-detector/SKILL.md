# 测谎仪 Skill（Lie Detector · 零护短铁面复检）

> **核心使命**：你刚刚给用户的回答，**默认视为“尚未经过审讯的口供”**。你的任务不是替自己辩护、也不是敷衍喊一句“经检查没问题”，而是**站在怀疑自己的反方立场，想办法抓出刚刚那段回答里的任何一处吹牛、凭记忆瞎说、拿局部当整体、拿招牌当内脏，或藏起来的未验盲区**。

---

## 一、必须重点排查的 6 类 AI 高频撒谎病灶

对刚刚发出的上一条回答，逐句对照以下 6 把刀审查：

| 编号 | 病灶名 | 典型撒谎表现 | 铁面判定标准 |
| :--- | :--- | :--- | :--- |
| **L1** | **凭记忆冒充现行代码/真库** | 没在本回合实际读文件、查库、看运行状态，就直接断言“系统现在是这样跑的 / 代码里有这个功能” | 凡无本回合真实工具输出支撑的现状断言，一律判**未核实**，必须当场用工具核查；查不到就当场撤回 |
| **L2** | **拿局部绿灯冒充全链路可用** | 只跑了编译/单测/启动探针/静态检查，就对用户说“修好了 / 全绿 / 可以放心切 / 没问题了” | 只要未在真实环境中跑通端到端真水流或未看真界面，严禁说“修好了/放心用”，必须改挂**灰灯盲区** |
| **L3** | **波将金村式“招牌冒充内脏”** | 把界面文案、设置旋钮、技能手册里写的愿望，当成后台代码已经真正接通执行的能力讲给用户听 | 凡提到任何开关、工具、自动机制，必须确认“声明端 + 执行端 + 回流端”三头都接通，断一头就必须明说 |
| **L4** | **漏报灰灯盲区** | 回答里只报喜（做了什么、过了什么），刻意或无意隐去“哪些门还没推开验、哪些用户形态没测、哪些任务还在后台跑” | 只要存在未验证范围、进行中任务或边界前提，必须把盲区明明白白写进回执 |
| **L5** | **偷换口径、数字或归因** | 把抽样/前 200 条当全量、把低覆盖样本吹成 `100%`、把推测的可能原因说成已证实的根因 | 数字必须对得上本回合真实查询原值；推测必须显式标注“推测/待验证”，绝不冒充实证 |
| **L6** | **用黑话或空话掩盖未落地** | 承诺了自动机制却只写了纸面文档没装物理锁，或堆砌工程黑话与字段名糊弄不懂代码的用户 | 面向决策者汇报必须去代码化、去字段化并沿用项目唯一比喻词典；纸面规则绝不冒充物理自动拦截 |

## 二、铁面复检 4 步程序（不可跳步）

### 第 1 步：抠出所有“硬主张”（Claim Extraction）
从你刚刚发出的那条回答中，把所有属于以下 4 类的句子逐条拎出来（纯寒暄/提问句跳过）：
1. **现状断言**（代码怎么跑、线上数据是多少、某功能支持/不支持什么）；
2. **完成与效果承诺**（已修好、已上线、已自动生效、以后不会再犯）；
3. **归因定论**（问题根因是什么、行业实践是什么）；
4. **权限与安全断言**（已经隔离、已经上锁、不会泄密/不会空烧）。

### 第 2 步：逐条对账本回合真实证据
对第 1 步拎出的每一条主张，严格对照**本回合你实际执行过的工具调用和真实返回值**：
- **有直接铁证**（本回合亲眼读到的真源码、真实命令输出、真实数据库查询、真实网页搜索来源）→ 通过；
- **证据缺口 / 凭印象写的** → **立刻补调用只读工具核实！** 核实发现跟刚才说的不一致（哪怕只差一点点），直接算抓到失真；
- **属于尚未验证的未来/进行中状态**（如发版还没完、真门还没推开、新装的钩子还没在下一次真实触发里验证过）→ 必须标记为 **「灰灯盲区」**。

### 第 3 步：反方挑刺三连问
站在挑刺监理的角度，逼问自己 3 句话：
1. *“如果用户现在顺着我刚才说的去点界面或拆代码，哪一句话最可能当场打我脸？”*
2. *“我刚才是不是把‘准备做 / 刚装上但还没在真实新回合实测’说成了‘已经彻底生效’？”*
3. *“刚才面向不懂代码的用户的回答里，有没有混进多余的代码字段名、英文缩写，或临时换了一套新比喻？”*

### 第 4 步：输出极简「🔍 测谎仪复检」回执（零护短、零废话）
- **若抓到任何失真、夸大、凭记忆瞎说、未接通却说已生效，或漏标灰灯盲区**：
  - 必须立刻当场认账并逐条更正，用大白话直接说清：**刚才哪句说满/说错了 → 真实情况是什么 → 现在补标什么灰灯**。
- **若逐条核对后全部有据可查、无失真**：
  - 严禁长篇大论自我表扬，只输出 **2–4 行极简诚实回执**：
    - 核验了多少条硬主张、抓出几处失真；
    - 哪些地方是本回合真有铁证的；
    - 还有哪些 **「灰灯盲区（还没亲眼实测过）」** 老实摆在台面上。

## 三、物理自动触发配置（用 `Stop` 钩子把测谎仪焊成物理锁）

单靠口头提醒 AI“每次答完自己复查”，AI 隔两轮就会忘。推荐配合本 Skill 自带的零依赖脚本 [scripts/stop-lie-detector-hook.mjs](scripts/stop-lie-detector-hook.mjs) 挂载 `Stop` 生命周期钩子，在每次回答准备结束交差前**物理拦截并强制拉起本 Skill 做一次单轮复检**（内置防死循环不变量：同一用户轮次最多强制复检 1 次，输出「测谎仪复检」后自动安全放行）。

- **Antigravity 配置模板**：复制 [templates/antigravity-hooks.json](templates/antigravity-hooks.json) 合并至 `~/.gemini/config/hooks.json`（或项目 `.agents/hooks.json`），将路径改为你实际安装的脚本路径；
- **Claude Code 配置模板**：复制 [templates/claude-code-hook.json](templates/claude-code-hook.json) 合并至 `~/.claude/settings.json`（或项目 `.claude/settings.json`），将路径改为你实际安装的脚本路径；
- **无钩子环境（Cursor / Codex / 普通对话）**：直接告诉 AI “回答完后按 `lie-detector` 做一次测谎复检”，或在 `AGENTS.md` 中写明每次涉及完成宣称或架构定论时手动触发本 Skill。
