# MISTAKE_BOOK.md — 项目活态错题本（含开源预装通用起步示范 · 托管于 GitHub `main` 唯一正本）

> **立本心法（写前必读）**：
> 过去已经修掉的具体老 Bug，明天不会原样再来一遍。如果把错题本写成“上次 `foo` 字段拼错了，下次记得检查 `foo`”，那只是在往未来每个 Agent 的脑子里灌废话。
>
> **本文件只记录两类真正值钱的资产**：
> 1. **思维跃迁示范（Few-Shot）**：记录一次真实的“停在原地糊眼前（第 0 层）→ 查十改十（第 1 层）→ 以系统架构师视角追出缺失原则并立硬机制防未来 1,000 个（第 2 层）”的完整升维过程；
> 2. **反复出现的顽固本能镜子**：记录团队或 AI 在被揭穿后仍容易换马甲复发的坏习惯，供独立审码官对照抓包。

---

## 零、活态错题本积累与淘汰 4 条铁律

1. **准入门槛**：只有以架构师视角追出**底层缺失编写原则**，或发现**跨模块反复换皮复发的坏习惯**时，才提炼入本；一次性笔误与已修老 Bug 绝不入本。
2. **GitHub 正本同步**：新增或修改错题条目必须随对应整改 PR **同船合入 GitHub `main`**，并注明关联 PR/Issue 编号，确保所有协作 Agent 共享同一份免疫记忆。
3. **写前先问能不能写成硬机制**：优先把教训固化成唯一协议表、编译期共享类型或极简机械门禁；机械能锁死的，就不靠文字提醒。
4. **定期做减法卸载**：当某条镜子已被编译器/门禁永久封死，或底层模型升级已原生做稳时，果断删去冗余条目，保持本文件极薄、高信噪比（建议常驻核心示范保持在 4–6 条内）。

## 一、预装通用「思维跃迁示范」（已脱敏 · 开箱即用，可按自家项目增删）

> 下方 4 条均提炼自真实高强度 AI 研发踩坑（已 100% 脱敏为行业通用工程案例），用来帮你的团队和 AI 一上手就明白“什么叫从架构层升维治本”。

### 示范 1 · 从“逐个对齐报错字段” → 追出「唯一契约与实时事件总表原则」
- **表面现象**：后台 150+ 个单元测试全绿上线，纯视觉黑盒实测 15 项却只过 4 项（验证码大小写死锁、前端建群和任务卡片两头各起一套字段名、定时任务展示与底层调度各记一张账本）。
- **第 0 层（原地踏步）**：把今天报出来的 3 个字段名逐个改对。
- **第 1 层（查十改十但未升维）**：全仓查出 7 处字段错位一并改齐——但明天开发新功能加上第 8 个字段，前后端照样各写一套。
- **第 2 层（架构师视角追原则 + 立硬机制）**：
  - **缺失的架构原则**：前后端各自凭记忆维护一份接口约定，错位在架构上是必然的——当初没有遵循**「以底座为基准立唯一协议与实时事件总表、写前读表写后核表、尽快编译期共享类型锁死」**的原则。
  - **顺原则全仓查一再查十**：横扫全仓筛出全部“底座已有但未直通前端”以及“前后端双头维护”的潜在错位点；
  - **永久硬机制**：在仓库根目录立死唯一 `PROTOCOL_FIELDS.md`（官方底座字段直通前端 + 自有业务沉淀为编译期共享类型包 + 实时推送事件名共享且前端一张表挂死事件与视图刷新映射），彻底堵死未来 1,000 个新字段错位。
- **一句生活比方**：买了一栋精装毛坯楼，装灯队和电工队各揣各的插座尺寸单，各自测电笔全亮绿灯，一装灯全插不上——必须全工地共用一张总水电规格表。

### 示范 2 · 从“给白屏页面加判空和偷补默认值” → 追出「AI ↔ 代码结构化交接 5 步原则」
- **表面现象**：AI 助理创建结构化任务卡时漏填“负责人姓名”、状态填了未约定简写，导致用户点进工作区整页白屏（还被外层兜底误报成“网络波动”）。
- **第 0 层（原地踏步）**：在前端到处加空值保护、在后端序列化时偷偷塞假默认值（缺名字填“待领命”、缺标题填“交付物 1”）——不仅掩盖上游病根，还把员工认真写的真实文件名盖丢了。
- **第 1 层（查到上游但未升维）**：发现发给 AI 的填表提示词没印清表头，只把这一张表的说明书补全再加点别名兼容。
- **第 2 层（架构师视角追原则 + 立硬机制）**：
  - **缺失的架构原则**：非确定性的大模型向确定性的代码递交结构化数据时，光靠口头嘱咐永远必炸——当初没有遵循**「AI ↔ 代码结构化交接 5 步闭环原则」**。
  - **顺原则全仓查一再查十**：立刻普查全仓所有由大模型提交结构化数据的工具/接口（协作、知识库、申请单、审批、排程……），一次性全部收口；
  - **永久硬机制（5 步交接铁律）**：① 第一棒同时给齐清晰表头 + 完整真实填表示例（枚举选择题必写明默认倾向、判定标准与防误判边界）；② 程序只检“必填不空 + 明确选对象时对象真实存在”（严禁审语义好坏、严禁偷补假默认值、严禁用代码静默勾选未完步骤宣告结束）；③ 不通过带明确原因打回大模型重填，再给 2 次机会；④ 连续 3 次未填对才正式触发程序报错；⑤ **正式程序报错也绝不直接拍到用户脸上，必须原样交还 Agent 处理或用人话向人解释**。
- **一句生活比方**：银行柜台怕客户经理填错转账单，绝不能后台偷偷把空卡号替换成默认账户硬转，更不能把机器英文乱码甩客户脸上——桌上摆表头+样板单，柜台只查必填不空和收款人真存在，不对退回经理重填（最多 3 次），真走不通仍由经理接住向客户交代。

### 示范 3 · 从“逐条糊掉 13 个 Bug” → 追出「同源机制归因 + 发现盲区自省 + 四方同步升级原则」
- **表面现象**：400+ 条模拟单元测试全绿上线，独立纯视觉黑盒压测 20 分钟当场点出 13 个真实缺陷（按钮点不动、卡片吐原始 JSON、切页面错投旧会话、并发扣款余额倒跳、任务缺件假完结等），而监控系统全程报绿。
- **第 0 层（原地踏步）**：把报出来的 13 个 Bug 按列表一条条修完收工。
- **第 1 层（只修症状不问雷达）**：修完这 13 处后依然依赖模拟单测上线，既没扫全仓兄弟点位，也没追问监控为何全程失明。
- **第 2 层（架构师视角追原则 + 立硬机制）**：
  - **缺失的架构原则**：把 13 个表面症状往架构层收拢，实为 4 大共同结构病（半截管道断在前端最后一公里 / 把瞬态意图当终态缺事实门禁 / 盲目头部截断与暴力整段覆写 / 守卫散落多入口）；同时缺失**「主动可观测自省」与「代码/提示词/字段表/验收口径四方同步升级」**原则。
  - **顺原则全仓查一再查十**：沿 4 条共同病根横扫全仓，额外挖出 30+ 处还没爆雷的同类兄弟隐患一次性清零；
  - **永久硬机制**：确立「结果交付唯一北极星（用户最终在屏幕上到底拿到真结果没有）」+ 每次重测彻底清零旧状态与旧缓存 + 任何改代码同步核查提示词/字段表/探针口径。
- **一句生活比方**：整栋楼装了同一批劣质水管接头，今天渗水的是 13 块瓷砖，只拿腻子糊平这 13 块，剩下 30 多个接头明天照样淹房子；更要追问一句“院里的漏水报警器昨晚为什么全程没响？”

### 示范 4 · 从“手连特定客户电脑救急” → 追出「全客户平等与产品自助可配置原则」
- **表面现象**：某个种子/创始账号在自己电脑上缺运行依赖或遇到双开冲突，开发第一反应提议“手动连上对方电脑杀进程装环境”，或在源码里为该账号写一条特判分支凑合过关。
- **第 0 层（原地踏步）**：工程师手连对方机器临时修好，或者代码里加 `if (tenant === 'vip')`。
- **第 2 层（架构师视角追原则 + 立硬机制）**：
  - **缺失的架构原则**：**「全客户平等与 SaaS 产品自助可配置原则」**——任何创始账号或大客户本质上都是普通用户，靠人工开小灶修环境或源码写特判，本质都在掩盖全平台普通用户必然踩到的真实产品缺口。
  - **顺原则全仓查一再查十**：横扫全仓清除所有单客户硬编码与后台暗门，并把“禁止单客户特判”写进极简机械门禁脚本；所有端侧缺口一律通过官方安装包、轻探针引导或服务端升级全员通用根治。
- **一句生活比方**：自家卖的净水器在老板家里漏水，研发绝不能只拿扳手跑去老板家拧紧就宣布合格，必须把出厂密封圈改对让所有买机器的顾客都不漏。

## 二、预装通用「防复发红线镜子」（专抓 AI 最顽固的换皮打补丁惯性）

> 下面 6 面镜子开箱即生效（前 5 面的逐轮打回原过程见 `first-principles-code-review/references/five-patch-mirrors.md`）；如果你的项目后续冒出新的跨模块顽固坏习惯，直接往表尾追加。

| 镜子名称 | 常见换皮马甲（抓包特征） | 一句生活比方 | 唯一正确落点 | 关联 PR |
| :--- | :--- | :--- | :--- | :-: |
| **1. 业务状态猜词与特例按钮** | 在基础工具里塞业务关键词表自动弹求助卡；拆完词表又换皮加“必须先查完所有标签页才准求助”的死流程锁，或单造一个场景特例按钮 | 不肯交出真鼠标键盘，非要搓一块每撞一次墙就多焊一个键的塑料遥控器 | 拆光基础工具里的业务 `if -> then`，收敛为纯净通用工具 + 物理断线的独立求助工具 | `预装` |
| **2. 自然语言前置扫词截胡** | 在用户的话进大模型之前，代码靠正则扫“每天”“每周”等关键词半路抢话头代建任务 | 老板和聪明助理之间塞了个只认两个字的耳背传话员，半路抢话乱下单 | 除用户亲手点击的界面显式按钮或明确斜杠命令外，自然语言 100% 原样直达大模型 | `预装` |
| **3. 过度设计黑盒转译中间关** | 模型编造参数就在门口写正则事后猜假词；拆掉正则后又过度设计“不管图、文还是常规文件，凡事必经程序黑盒转译再给模型” | 员工肉眼能直接看懂的照片和短单子，硬逼前台翻译一遍再递给他 | 模型能原生直读的直接交有能力模型读（读不了就换支持该能力的模型），确实读不了坦诚直说；仅物理绕不开的确定性计算/二进制/句柄注入交工具 | `预装` |
| **4. 拍脑袋大小阈值静默截断** | 代码写死 `slice(0, 600)` 丢弃后半截；拆完又换皮改成“程序设个字数阈值，超长就自动替模型改写摘要” | 递给助理一本厚书，前台先拿尺子量厚度、超 10 页就把后半本撕掉重抄 | 拆光静默截断和拍脑袋阈值，给工具配目录/分页按需读取，策略写进提示词 | `预装` |
| **5. 暗藏打扰弹窗与擅自掐循环** | 后台高频定时循环里暗藏系统授权弹窗；被抓包后叠三层防抖冷却，还顺手写死“循环遇报错直接停掉” | 授权弹窗接在后台闹钟上乱弹；路走不通时工具擅自判整趟业务死刑 | 授权/审批剥离为独立显式工具；任何运行报错既不蒙头硬撞也不擅自掐死流程，一律原样交还大模型判断 | `预装` |
| **6. 假 `0` 兜底与微整数混口径** | 前端加载中或接口报错时拿 `0` 顶数冒充真余额/真件数；后端把防浮点误差的百万倍微整数直接混在返回里递给大模型读 | 汽车仪表盘断电了不亮红灯，反而把指针硬停在 `0` 骗司机油箱空了 | 前端严格区分 `loading / error / empty / zero` 四态；递给大模型读的账目只给带明确单位的人类口径 | `预装` |
