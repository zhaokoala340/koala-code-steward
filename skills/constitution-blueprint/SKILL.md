# 研发宪法与产品蓝图（Constitution & Product Blueprint）

> **核心理念**：写代码之前不把“盖什么、不盖什么、借什么底座、Agent 和代码谁管哪块、接口字段叫什么、错题怎么攒”白纸黑字锁进 GitHub 正本，AI 就一定会凭脑补自由发挥——最后造出一堆重复轮子和彼此打架的补丁。

---

## 一、开工前先备好共建工具与参考资料

- **强烈推荐联动开源 Skill `grill-me`（[`mattpocock/skills`](https://github.com/mattpocock/skills)）帮用户共建宪法与蓝图**：
  - 安装方式：`npx skills@latest add mattpocock/skills --skill=grill-me`
  - **为什么联动 `grill-me`？** 很多时候用户脑子里对“产品边界、取舍、反边界”只有模糊轮廓。如果直接让 AI 生成蓝图，AI 会顺着模糊提示编出一份“看似完整实则全是脑补”的文档。先调用 `grill-me` 顺着决策树逐枝追问，才能把真正隐含的决策点全部磨清。
  - **执行规则**：若当前环境已安装 `grill-me`，直接按其协议发起逐轮访谈；若未安装，则按下方内置的 **Grill-Me 决策树访谈法** 执行。
- **Agent 与代码协同边界详拆**（含 3 句试金石、AI↔代码 5 步结构化交接铁律、9 组通用正反例与错题本积累法则）：[references/two-boundaries-guide.md](references/two-boundaries-guide.md)
- **开箱五件套模板（100% 自包含，位于 `templates/`）**：
  - [templates/AGENTS_TEMPLATE.md](templates/AGENTS_TEMPLATE.md)（复制到项目根目录作为 `AGENTS.md`）
  - [templates/PRODUCT_BLUEPRINT.md](templates/PRODUCT_BLUEPRINT.md)
  - [templates/PROTOCOL_FIELDS.md](templates/PROTOCOL_FIELDS.md)
  - [templates/BOUNDARIES.md](templates/BOUNDARIES.md)
  - [templates/MISTAKE_BOOK_TEMPLATE.md](templates/MISTAKE_BOOK_TEMPLATE.md)（复制到项目根目录作为 `MISTAKE_BOOK.md`）

## 二、五步第一性原理立宪流程（严禁跳过直接写代码）

### 第 1 步：用 `grill-me` 决策树访谈法，和用户共建「产品是什么、不是什么」
不要一次甩 20 道问卷轰炸用户，也绝不顺着模糊需求直接脑补拍板。严格按 **`grill-me` 决策树前沿访谈法** 推进：
- **能查已有代码/仓库先自己查**：凡能从现有代码或文档确认的事实，先查图谱和真源码，不拿已知问题烦用户；
- **每轮只问当前决策前沿的 1–3 个关键分叉问题，并附带你的推荐选项与理由**，待用户拍板后再顺着选定分支往下追问；
- **歧义未磨透前，严禁提前动笔写业务代码**。

访谈必须把以下 6 个根问题全部钉死：
1. **产品是什么**：一句话大白话说清它在真实世界解决哪 1–3 个核心痛点？
2. **定死「本项目唯一系统比喻词典」**：基于产品真实的业务与代码运转逻辑，和用户一起确定**一套贯穿整个项目生命周期的固定比喻映射表**（写入 `PRODUCT_BLUEPRINT.md` §1.2）。**为什么必须定死？** 因为默认用户不懂代码和编程，后续所有对话、所有不同 Agent 面向用户解释细节时都必须沿用同一套比喻——绝不能今天用开餐馆、明天用盖大楼、后天用坐火车，给用户增加额外认知负担。
3. **服务谁、交付什么可见结果**：不同角色在屏幕上最终拿到什么才算真的帮到他们？
4. **产品不是什么（最关键的反边界）**：白纸黑字列出 **3–5 条明确不做、刻意砍掉或暂不做的事**，堵死 AI“顺手补齐行业标配”的膨胀本能。
5. **封闭能力清单**：盘点本期交付模块并编号——清单之外的新模块、新数据表、对模型可见的新工具或后台循环，AI 觉得“顺手加一个”一律算违规。
6. **不可妥协的底线**：如全用户平等隔离（零单客户特判）、顺人性不设繁琐卡点、高危动作必经真人批准、诚实状态（没完成绝不标完成、绝不拿假 `0` 顶数）。

### 第 2 步：切换「系统架构师」身份，划死第一道线（底座 vs 素描模特 vs 自研薄层）

> **【身份切换提示词 · 架构定界阶段】**
> 产品“是什么、不是什么”通过 `grill-me` 磨清后，请从“产品访谈官”切换为**「系统架构师」**身份：跳出旧代码惯性，从**数据唯一真源、模块低耦合、100 倍量级承压与长期可演化性**出发，划定底座、自研、代码与提示词的全部架构边界。

动笔设计前，先核查现有可靠开源实现与底层底座：
1. **底层官方底座（已获授权引入的基础设施）**：底座现成有的 0 行自研，原则上不 Fork、不打 patch、不魔改；底座留了插座的只写薄适配，确需替换底座内置模块前必通读原模块全源码。
2. **明确可靠的行业开源项目 = 「素描模特」（降幻觉，但未经授权绝不直接搬运）**：
   - 如果用户研究的领域存在明确可靠的开源代码，**允许且鼓励先去读它的真实代码结构，评估其模块划分、边界设计、状态机与容错思路是否适用**——就像画画前摆一位真实的素描模特，防止 AI 凭自己脑子脑补现实中不存在的东西，显著降低幻觉概率；
   - **原则上，除非用户明确授权，绝不直接引用、复制或把别人的开源代码当依赖塞进自家仓库**（避免许可证风险、供应链包袱与照抄出“虚幻接口”）。
3. **自研核心护城河**：只把底座彻底没有、且属于自身差异化价值的部分列入封闭清单。

### 第 3 步：写透 Agent 与代码协同的第二道线（以及活态错题本机制）
> 凡涉及 Agent（大模型）与确定性代码协同的系统，必须把以下 **3 件事** 白纸黑字锁进 `BOUNDARIES.md` 与 `MISTAKE_BOOK.md`（详拆见 [references/two-boundaries-guide.md](references/two-boundaries-guide.md)）：

1. **核心两层职责边界（代码层 vs 提示词层）+ 快模型按需推荐**：
   - **代码层**：物理隔离与权限铁锁、资金账本与风控熔断、确定性计算与客观台账、纯净通用工具、**纯可执行性结构校验**、零干扰异常探针、真实报错原样透传；
   - **提示词层**：听懂自然语言意图、看懂现场上下文、大文档按需阅读策略、敏感与轻重判断、多角色协商、遇报错决策换路或向人交代；把“只许写进提示词、进代码即违宪”的规则单列成封闭红线表；
   - **快模型（按需推荐的可选衔接方案，非必选项）**：普通系统无需强行引入快模型；仅在确实适合的场景（如外部群聊实时旁听分诊、旁路零干扰结果交付 `YES/NO` 探针等需要把模糊判断低成本转为代码可执行信号的灰区边界）下，可向用户**推荐**采用快模型衔接——且严禁拦在系统内 1 对 1 门口，严禁拿弱模型替代主力大脑降智省钱。
2. **AI ↔ 代码结构化交接 5 步铁律**：
   - ① 第一棒给齐清晰表头 + 真实参考写法示例（枚举选择题必写默认倾向与防误判边界）；
   - ② 程序**只检必填不空 + 选对象时对象真实存在**（严禁审语义好坏、严禁后台偷补假默认值、严禁用代码静默勾选未完步骤宣告结束）；
   - ③ 不通过带明确原因打回大模型重填，再给 2 次机会；
   - ④ 连续 3 次未通过才正式触发程序报错；
   - ⑤ **正式程序报错也绝不直接拍到用户脸上，必须交还给 Agent 处理或用人话向人解释**。
3. **活态错题本积累与淘汰规则**：
   - **只记两类值钱资产**：① 追出缺失原则的「第 0 层 → 第 2 层思维跃迁示范」；② 跨模块反复换马甲复发的「顽固补丁镜子」；
   - **坚决不记已修老 Bug 流水账**（避免废上下文把 AI 脑子撑糊涂）；
   - **必须入 GitHub 正本并定期做减法**：一旦原则已通过编译器、机械门禁或更强模型彻底根除，果断从错题本里卸载，保持极薄高信噪比。

### 第 4 步：立死唯一协议与字段总表（`PROTOCOL_FIELDS.md`）
- 底座已有协议字段直接向其靠拢一竿子贯通到前端，绝不双写两张账本；
- 自有业务接口请求/响应、大小写归一化规则、人类可读单位（绝不把底层微整数直接混给大模型读）、以及**前后端实时推送事件与视图刷新映射表**统一入表，编码阶段尽早落成编译期共享类型包。

### 第 5 步：外置五件套 → 白话对齐拍板 → 提交至 GitHub `main` 作为唯一正本
1. 将五件套文档写入仓库根目录（并搭配 `github-shared-truth` 落好 `.github/pull_request_template.md` 与 `docs/decisions/`）；
2. **面向决策者汇报确认（默认用户不懂代码）**：严禁甩一串字段名、表名、英文缩写或代码黑话，也不要只喊空泛口号——严格沿用刚刚敲定的**本项目唯一比喻词典**，把核心边界、反边界、运行细节与真实代价讲透，获批后提交并合入 **GitHub `main`**。从此所有来干活的 coding Agent 全部以 GitHub `main` 为共同上下文正本。

## 三、动笔写业务代码前 9 项过关自检

- [ ] **已走 `grill-me` 深度对齐**：核心歧义与设计分叉已逐枝确认，非 AI 自行脑补。
- [ ] **是什么 / 不是什么清晰**：产品定位、痛点与至少 3 条“明确不做 / 暂不做”已锁死。
- [ ] **封闭清单锁死**：本期所有模块、数据表、关键工具已编号，写明清单外“顺手加一个”即违规。
- [ ] **素描模特与底座界限清澈**：已核查底座真源码或可靠开源“素描模特”降低幻觉，且严守未经明确授权不直接搬运/引入他方开源代码。
- [ ] **Agent 与代码边界写透**：已列“只许写进提示词”清单，已明确 AI↔代码 5 步结构化交接铁律与 5 面硬镜子红线。
- [ ] **唯一契约落盘**：`PROTOCOL_FIELDS.md` 已覆盖底座字段直通、自有核心接口与实时推送事件刷新表。
- [ ] **活态错题本机制就位**：仓库已落盘 `MISTAKE_BOOK.md`，明确只记思维跃迁与顽固镜子、不堆老 Bug 废话。
- [ ] **GitHub 唯一正本已建仓入库**：五件套文档与 PR 留痕模板已提交至 GitHub `main`，多 Agent 共享同一真源。
- [ ] **决策者白话拍板**：已用生活化大白话讲透边界与代价并获确认。
