# 三组「思维跃迁阶梯示范」（Few-Shot · 第 0 层 → 第 2 层）

> **阅读心法**：下面三组案例展示的不是“让你背几个旧 Bug 的修法”，而是示范**面对未来任何从未见过的陌生问题时，思考必须完成的向上拔一层动作**——从“修眼前 1 个”，到“查 10 改 10”，最终升维到“立原则与硬机制防未来 1,000 个”。

---

## 阶梯示范 A · 从“去对齐几个报错字段” → 追出“唯一契约总表原则”

- **表面现象**：后台 150+ 个单元测试全绿上线，纯视觉黑盒验收 15 项却只过 4 项（邀请码大小写死锁、前端建群和任务卡字段两头各起一套名字、定时任务展示与底层引擎各记一张账本）。
- **第 0 层 · 原地踏步**：把今天报错的那 3 个字段名逐个改对。
- **第 1 层 · 查十改十但未定性**：全仓查出 7 处字段错位一并对齐 → **隐患仍在：明天开发新功能加上第 8 个字段，前后端照样各写一套！**
- **第 2 层 · 追问缺失原则 + 升维定性**：
  - **当初没遵循什么原则**：“只要前后端各自凭记忆维护一份接口约定，错位是必然的——当初没有遵循‘以底层底座为基准立一份唯一接口、字段与实时事件总表，写前读表、写完对表’的原则。”
  - **顺原则查一再查十**：拿着这条原则横扫全仓，立刻筛出所有“底层框架已有但未直通前端”以及“前后端双头维护”的潜在错位点；
  - **升维硬机制**：设立根目录唯一 `PROTOCOL_FIELDS.md`（① 官方底座字段直通前端；② 自有业务尽快沉淀为共享类型包由编译器机械锁死；③ 实时推送事件名编译期共享，前端用一张清晰表把事件与视图刷新全量挂死）——彻底堵死未来 1,000 个新字段错位。

## 阶梯示范 B · 从“给崩掉的页面加判空” → 追出“AI ↔ 代码结构化交接原则”（产品含大模型时适用）

- **表面现象**：AI 助理在群里创建任务卡时漏填“负责人姓名”、状态用了未约定的英文简写，导致用户点进工作区整页白屏（还被外层兜底误报成“网络波动”）。
- **第 0 层 · 原地踏步**：给前端加上空值保护、在后端偷偷塞假默认值（缺名字填“待领命”、缺标题填“交付物 1”）——结果不仅掩盖了上游问题，还把认真写的真实文件名给盖丢了。
- **第 1 层 · 查到上游但未定性**：发现发给 AI 的空白填表说明书没印清楚 → 只把任务卡这 1 张表的提示词补全 + 后端加别名兼容。
- **第 2 层 · 追问缺失原则 + 升维定性**：
  - **当初没遵循什么原则**：“非确定性的大模型向确定性的代码递交结构化数据时，只靠口头嘱咐永远必炸——当初没有遵循‘AI ↔ 代码结构化交接 5 步闭环原则’。”
  - **顺原则查一再查十**：既然当初没遵循这条原则，全仓所有让大模型填结构化参数的工具与插件（协作、知识库、申请单、审批、排程……）必然全埋着同类雷！立刻先全仓普查出完整接口清单；
  - **升维硬机制（5 步交接铁律）**：
    1. 第一棒同时给齐**清晰表头 + 完整真实填表示例**（凡枚举/档位类选择题，必同时写明默认倾向、判定标准与防误判边界）；
    2. 大模型按 Schema 提交后，程序**只检“必填不空 + 明确选对象时对象真实存在”**（严禁审文采/全面性等模糊语义，严禁偷偷补假默认值，严禁用代码静默抹平自相矛盾或自动勾选未完步骤宣告结束）；
    3. 不通过时带着明确具体原因打回给大模型重填，再给 2 次机会；
    4. 连续 3 次未通过才正式触发程序报错（防止无限循环烧算力）；
    5. **哪怕正式触发程序报错，也绝不把冷冰冰的程序报错直接拍到用户脸上，必须原样交还给 Agent，由 Agent 决定换路处理或用人话向人解释原因**。
  - **同源延伸**：前端加载中/读取失败绝不拿假 `0` 冒充真 `0`；后端递给大模型读的账目只给带明确单位的人类口径，绝不混入底层防浮点误差的百万倍微整数。

## 阶梯示范 C · 其余三把高频「缺失原则」对照梯子

| 表面踩到的坑 | 原地踏步的修法（第 0 层） | 追出缺失原则 → 顺原则扫全仓 + 升维定性（第 2 层） |
| :--- | :--- | :--- |
| 端侧工具箱缺失，系统反盖“已完成”章 | 让客户端找不到工具箱时如实报错 | **缺失「多端四方同步升级原则」**：迭代只改了代码，忘了同步提示词、唯一字段表和监控探针口径 → 顺原则全仓排查所有“代码已升但提示词/探针还停在旧版”的隐患，立四方联锁同步纪律。 |
| 20 条接口数据被截断只剩 1 条 | 给这 20 条写个“按条数均分字数”的算法 | **缺失「天生扛 100 倍真实量级原则」**：按小样本拍脑袋写裁剪，遇上几百份两万字原件或百万行记录必再叠补丁 → 顺原则扫全仓所有“暗含数据量很小”的链路，改用按需分页、目录索引与计算下推机制。 |
| 创始账号/大客户端侧缺组件或要特殊定制 | 工程师手动连客户电脑装依赖，或在源码里为某账号写特判 | **缺失「全客户平等与产品自助可配置原则」**：任何特权账号本质上都是普通客户，靠人工救急或后台开小灶都在掩盖真实产品缺口 → 顺原则扫全仓单客户硬编码与暗门，全部升维为通用安装包、轻探针引导与自助配置能力。 |
